# AI Strategy

## Core position

AI is the **interpretation, enrichment, inference, retrieval, reasoning, and conversational layer** over a deterministic financial core.

AI is not the authoritative source of financial truth.

## AI job categories

### 1. Extraction

Convert messy sources into candidate structured facts.

Sources may include:

- bank descriptions,
- SMS,
- email,
- PDF statements,
- invoices,
- receipt images,
- screenshots,
- imported files,
- natural-language user input.

Examples:

```text
BLINKIT 2846
→ merchant candidate: Blinkit
→ amount candidate: ₹2,846
```

```text
Amul Fresh Paneer 200g x2 ₹180
→ product: paneer
→ brand: Amul
→ quantity: 400g
→ price: ₹180
```

### 2. Classification

Classify merchants, categories, products, intents, contexts, etc.

### 3. Entity resolution

Normalize noisy names to stable entities.

Examples:

- `SWIGGY*ORDER`
- `SWIGGY IN`
- `SWIGGY BANGALORE`

may resolve to the same merchant entity.

### 4. Inference

Infer values when evidence is incomplete.

Examples:

- likely beneficiary,
- likely consumer,
- likely category,
- likely recurring pattern.

Inference must remain distinguishable from fact.

### 5. Personalization / default learning

Learn repeated user behavior.

Example:

```text
Protein powder → usually brother
Milk → usually household
Paneer → usually user
```

These become defaults or priors, not immutable truth.

### 6. Ambiguity resolution

Combine evidence from multiple sources and historical context.

Example:

Bank transaction alone is ambiguous; a matching email receipt can make the item identity more certain.

### 7. Natural-language query planning

Turn questions into structured retrieval/calculation plans.

Example:

> “How much did I personally consume on food last month?”

Potential plan:

1. retrieve food-related events,
2. inspect item allocations/consumption,
3. exclude household/other-person portions,
4. apply time filter,
5. calculate deterministically,
6. explain result.

### 8. Analysis and explanation

AI can explain deterministic results:

> “Food spending was ₹8,400 higher, primarily because restaurant spending increased by ₹6,100.”

### 9. Conversational interface

AI can be the natural-language interface to the financial graph and query system.

## AI must NOT

AI must not:

- invent transaction facts,
- silently modify authoritative financial records,
- perform financial arithmetic when deterministic calculation is available,
- treat low-confidence inference as certain,
- hide conflicting evidence,
- become the canonical database,
- create irreversible external financial actions without explicit product policy and user authorization.

## Suggested architecture

```text
RAW SOURCES
  ↓
AI extraction / normalization
  ↓
candidate facts + provenance + confidence
  ↓
validation / deterministic rules
  ↓
financial domain model
  ↓
facts + defaults + inferences + relationships
  ↓
deterministic analytics/query engine
  ↓
AI reasoning / explanation
  ↓
user
```

## Model strategy

Do not hard-couple the product to one model provider.

Use a model-router approach where the task determines the model tier.

### Fast/cheap model

Use for high-volume simple work:

- obvious classification,
- merchant normalization,
- basic extraction,
- duplicate/near-duplicate detection,
- straightforward default application.

### Strong multimodal model

Use for:

- receipts,
- invoices,
- screenshots,
- PDFs,
- complex document extraction,
- messy product parsing.

A strong multimodal family such as current Gemini models is a natural candidate, but the final decision should be based on an application-specific benchmark, not generic model reputation.

### Strong reasoning model

Use selectively for:

- complex financial questions,
- cross-domain analysis,
- hypothesis generation,
- ambiguous multi-step interpretation.

## Model selection criteria

Benchmark real data on:

- structured extraction accuracy,
- hallucination rate,
- confidence calibration,
- entity resolution quality,
- product/brand extraction accuracy,
- ability to preserve unknowns,
- correction rate after human review,
- latency,
- cost,
- tool/function-calling reliability,
- multilingual/Indian-data robustness where relevant.

## Confidence-driven UX

The system should combine confidence and impact.

Example:

```text
Merchant = Blinkit
confidence = 0.99
→ auto-accept

Category = Groceries
confidence = 0.98
→ auto-accept

Consumer = Brother
confidence = 0.71
→ store as inference / maybe ask later

Product = Unknown
confidence = 0.18
→ keep unknown
```

Do not assume a universal confidence threshold. Thresholds should depend on the consequence of being wrong.

## AI memory / user model

The system may maintain learned patterns such as:

- merchant preferences,
- product-to-person defaults,
- category rules,
- recurring patterns,
- preferred vocabulary,
- household members,
- common contexts.

Memory must remain inspectable, overridable, and eventually forgettable by the user.

## Evaluation philosophy

AI quality should be measured by **financial usefulness and trustworthiness**, not only language quality.

An answer that is beautifully phrased but based on incorrect attribution is a product failure.
