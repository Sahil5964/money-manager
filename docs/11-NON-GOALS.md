# Non-Goals and Boundaries

This document prevents the project's ambition from accidentally becoming unlimited scope.

## Not a conventional accounting system by default

The initial product does not need to reproduce every feature of formal accounting software.

Accounting-grade behavior may be added where it creates user value, but the conceptual model should not be constrained by traditional bookkeeping terminology.

## Not a mandatory personal-finance questionnaire

Users should never be required to specify every role, split, product, or context for every event.

## Not an AI-only system

The product should remain useful and trustworthy when AI is unavailable or uncertain.

## Not a chatbot-first product

Conversation is an interface to a deeper financial model, not the product itself.

## Not an automatic financial decision-maker

Long-term recommendations may exist, but irreversible or high-impact financial actions require explicit policy, controls, and user authorization.

## Not a perfect reconstruction of reality

Some facts will remain unknown. The system should represent uncertainty rather than pretend to know everything.

## Not feature completeness for its own sake

New data dimensions should earn their complexity by enabling meaningful questions, decisions, or automation.

## Not a requirement to expose the whole model to every user

The underlying model may be rich while the visible UI remains simple.
