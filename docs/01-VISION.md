# Product Vision

## North star

Build a money-management system that can gradually understand a person's financial life without requiring them to perform bookkeeping.

The system should work for a person who only wants basic transaction tracking and for a power user who wants detailed understanding of people, products, consumption, obligations, context, and financial behavior.

## Core product thesis

> **A financial event is useful even when very little is known about it. Additional information should progressively increase the questions the system can answer.**

This means the product must not make rich financial modeling mandatory.

A user should be able to record:

> `₹500`

and be done.

The system may later learn or receive:

- merchant,
- category,
- products,
- quantities,
- people involved,
- beneficiary,
- consumer,
- ownership/economic responsibility,
- reimbursement expectations,
- context,
- intent,
- lifecycle,
- recurrence,
- and other evidence.

## What makes the product different

Traditional money managers usually treat a transaction as a mostly complete object and ask the user to classify it.

This product treats a financial event as a **progressively enriched model**.

The system should distinguish:

- cash movement,
- economic responsibility,
- benefit,
- consumption,
- obligations,
- assets,
- context,
- and uncertainty.

These dimensions can coexist without forcing them into a single category.

## Long-term ambition

The product can evolve from:

> money tracker → financial memory → financial understanding → financial intelligence

The eventual system should be able to answer questions about:

- where money went,
- who benefited,
- what was bought,
- what was actually consumed,
- what is owed,
- what patterns are changing,
- what is likely to happen next,
- and what choices might change the outcome.

## User experience north star

The user should primarily **review and correct** the system rather than manually construct every financial record.

Good experience:

> “I think ₹900 of this order was for your brother.”
>
> `[Confirm] [Edit]`

Bad experience:

> “Please fill 11 required fields before saving this transaction.”

## AI north star

AI should act as an interpretation, inference, retrieval, and explanation layer over a deterministic financial core.

AI may propose knowledge.

The financial system must remain able to distinguish authoritative facts from assumptions and inferences.

## Product promise in one sentence

> **Start simple, become increasingly intelligent, and never force the user to become an accountant.**
